## 7.1 运行维护基本概念

### 一、教学目标

掌握信息系统运行维护的概念、内容、流程以及ITIL/ITSM框架。

### 二、核心讲解

#### 1. 运维的定义

信息系统运行维护是指在信息系统投入使用后，为保证系统正常、高效运行，对系统进行的监控、管理、维护和改进等活动。

## 7.2 运维内容

### 一、核心讲解

#### 1. 运维主要内容

<Card title="运维八大内容" icon="information">
1. **日常监控**：系统运行状态监控
2. **故障处理**：及时响应和处理故障
3. **性能优化**：提升系统性能
4. **备份恢复**：数据备份和灾难恢复
5. **安全管理**：安全策略和防护
6. **配置管理**：配置变更管理
7. **容量管理**：资源规划和扩容
8. **文档管理**：运维文档维护
</Card>

#### 2. 备份策略

<MemoryCard 
  title="三大备份策略"
  formula="完全备份、增量备份、差异备份"
  importance={5}
  category="formula"
/>

| 备份方式 | 说明 | 优点 | 缺点 |
|----------|------|------|------|
| **完全备份** | 备份所有数据 | 恢复快速 | 时间长、空间大 |
| **增量备份** | 备份上次备份后的变化 | 速度快、空间小 | 恢复复杂 |
| **差异备份** | 备份上次完全备份后的变化 | 恢复较快 | 占用空间逐渐增大 |

## 7.3 ITIL框架

### 一、核心讲解

#### 1. ITIL定义

IT基础架构库(IT Infrastructure Library)是关于IT服务管理的最佳实践框架。

#### 2. ITIL v3核心内容（五阶段）

<MemoryCard 
  title="ITIL v3五阶段"
  formula="战略→设计→转换→运营→持续改进"
  importance={5}
  category="formula"
/>

| 阶段 | 说明 |
|------|------|
| **服务战略** | 定义IT服务战略 |
| **服务设计** | 设计IT服务解决方案 |
| **服务转换** | 构建和部署IT服务 |
| **服务运营** | 提供和支持IT服务 |
| **持续服务改进** | 不断改进服务质量 |

#### 3. ITIL核心流程

<Card title="服务运营五大流程" icon="information">
1. **事件管理**：快速恢复正常服务
2. **问题管理**：找出根本原因，防止再发
3. **变更管理**：控制变更风险
4. **配置管理**：维护配置项数据库(CMDB)
5. **发布管理**：控制发布和部署
</Card>

## 7.4 运维管理体系

### 一、核心讲解

#### 1. ITSM（IT服务管理）

基于ITIL的IT服务管理实践，强调以客户为中心提供IT服务。

#### 2. 运维管理关键指标

<MemoryCard 
  title="运维KPI指标"
  formula="可用性、响应时间、故障率、恢复时间"
  importance={4}
  category="key-point"
/>

| 指标 | 说明 | 计算公式 |
|------|------|----------|
| **可用性** | 系统正常运行时间占比 | (总时间-故障时间)/总时间×100% |
| **MTBF** | 平均无故障时间 | 总运行时间/故障次数 |
| **MTTR** | 平均修复时间 | 总修复时间/故障次数 |
| **SLA** | 服务水平协议 | 服务质量承诺 |

#### 3. 灾难恢复

| 指标 | 说明 |
|------|------|
| **RPO** | 恢复点目标，允许丢失的数据量 |
| **RTO** | 恢复时间目标，允许的中断时间 |

## 7.5 DevOps

### 一、核心讲解

#### 1. DevOps概念

DevOps是开发(Development)和运维(Operations)的组合，强调开发与运维的协作和自动化。

#### 2. DevOps核心实践

<Card title="DevOps关键实践" icon="information">
- **持续集成(CI)**：频繁合并代码
- **持续交付(CD)**：自动化部署
- **基础设施即代码(IaC)**：代码化管理基础设施
- **监控和日志**：实时监控系统状态
- **微服务架构**：服务解耦
</Card>

<ExerciseBox
  questionId="ch07-01-adv"
  question="某数据中心在每周日凌晨2点进行一次完全备份，周一至周六凌晨2点进行差异备份。如果周四上午10点数据库发生故障导致数据丢失，恢复数据时需要用到（ ）"
  options={[
    "A. 仅周日的完全备份",
    "B. 周日的完全备份 + 周一、周二、周三的差异备份",
    "C. 周日的完全备份 + 周三的差异备份",
    "D. 周日的完全备份 + 周三的差异备份 + 周四的日志"
  ]}
  answer="D"
  explanation="【真题考点：备份恢复策略】\n- 差异备份：备份自上次'完全备份'以来变化的数据。所以周三的差异备份已经包含了周一和周二的变化。\n- 恢复路径：\n  1. 恢复周日完全备份（基石）。\n  2. 恢复周三的差异备份（恢复到周四凌晨2点的状态）。\n  3. 恢复周四凌晨2点到上午10点的事务日志（如果日志还在，这一步能恢复最新数据）。\n选项C只恢复到了凌晨，选项D最完整。"
/>

<ExerciseBox
  questionId="ch07-02-adv"
  question="某系统平均运行1000小时才发生一次故障，故障后平均需要2小时修复。该系统的可用性（Availability）计算式是（ ）"
  options={[
    "A. 1000 / (1000 + 2)",
    "B. 1000 / 2",
    "C. (1000 - 2) / 1000",
    "D. 2 / 1000"
  ]}
  answer="A"
  explanation="【真题考点：可用性计算】\n- MTBF（平均无故障时间）= 1000小时\n- MTTR（平均修复时间）= 2小时\n- 可用性 = MTBF / (MTBF + MTTR) = 1000 / 1002 ≈ 99.8%\n记忆：正常工作时间 / (正常工作时间 + 修理时间)"
/>

<ExerciseBox
  questionId="ch07-03-adv"
  question="运维团队接到用户报告：'网页访问速度非常慢'。运维人员查看监控发现Web服务器CPU利用率达到99%。根据ITIL服务运营流程，处理此事的正确顺序是（ ）"
  options={[
    "A. 立即重启服务器（事件管理） -> 分析日志找原因（问题管理）",
    "B. 先分析日志找根本原因，找到了再处理，以免破坏现场",
    "C. 提交变更申请，升级服务器CPU配置",
    "D. 忽略，等待CPU自动降下来"
  ]}
  answer="A"
  explanation="【真题考点：事件管理 vs 问题管理】\n- 事件管理的目标：'尽快恢复服务'。哪怕是重启、切备机这种治标不治本的方法，只要能让用户先用上，就是对的。\n- 问题管理的目标：'找到根本原因，彻底解决'。这是后续的动作。\n运维第一原则是'先通后排'。"
/>

## 重点总结

### 本章必记考点 ⭐⭐⭐⭐

1. **运维目标**：稳定性、可用性、性能、安全性

7. **DevOps实践**：CI/CD、IaC、监控、微服务
