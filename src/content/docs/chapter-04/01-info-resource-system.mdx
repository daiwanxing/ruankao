## 4.1 数据库系统

### 一、教学目标

掌握数据库系统的概念、组成、数据模型、范式和事务管理。

### 二、核心讲解

#### 1. 数据库系统组成

<MemoryCard 
  title="数据库系统三层模式"
  formula="外模式→模式→内模式（用户→逻辑→物理）"
  importance={5}
  category="formula"
/>

| 模式 | 说明 |
|------|------|
| **外模式** | 用户视图，某一用户看到的数据库逻辑表示 |
| **模式** | 逻辑模式，数据库总体逻辑结构的描述 |
| **内模式** | 存储模式，数据物理存储结构的描述 |

#### 2. 数据模型

| 数据模型 | 特点 |
|----------|------|
| **层次模型** | 树形结构 |
| **网状模型** | 图形结构 |
| **关系模型** | 二维表结构（最常用） |

#### 3. 数据库范式

<MemoryCard 
  title="范式口诀"
  formula="一原二完三传（1NF原子性、2NF完全依赖、3NF消除传递依赖）"
  importance={4}
  category="key-point"
/>

| 范式 | 要求 |
|------|------|
| **第一范式(1NF)** | 属性不可分割（原子性） |
| **第二范式(2NF)** | 满足1NF，且非主属性完全依赖主键 |
| **第三范式(3NF)** | 满足2NF，且消除传递依赖 |
| **BC范式(BCNF)** | 更严格的3NF |

#### 4. 事务特性（ACID）

<MemoryCard 
  title="ACID特性"
  formula="原一隔持（原子性、一致性、隔离性、持久性）"
  importance={5}
  category="formula"
/>

| 特性 | 说明 |
|------|------|
| **原子性(Atomicity)** | 事务中的操作要么全做，要么全不做 |
| **一致性(Consistency)** | 事务执行后，数据库保持一致性状态 |
| **隔离性(Isolation)** | 并发事务之间相互隔离 |
| **持久性(Durability)** | 事务一旦提交，结果永久保存 |

## 4.2 数据仓库

### 一、核心讲解

#### 1. 数据仓库vs数据库

| 特性 | 数据库 | 数据仓库 |
|------|--------|----------|
| **用途** | 日常业务处理(OLTP) | 决策支持(OLAP) |
| **数据量** | 小到中等 | 海量 |
| **操作** | 增删改查 | 主要查询分析 |
| **数据时效性** | 当前数据 | 历史+当前数据 |

#### 2. 数据仓库特点

<Card title="数据仓库四特性" icon="information">
- **面向主题**：按主题组织数据
- **集成性**：来自不同数据源的集成
- **相对稳定**：主要进行查询操作
- **随时间变化**：保存历史数据
</Card>

<ExerciseBox
  questionId="ch04-01-adv"
  question="某银行的转账系统在处理一笔从A账户扣款并向B账户入账的交易时，因网络故障导致扣款成功但入账失败。数据库系统立刻回滚了扣款操作，确保A账户余额未减少。这一机制体现了事务的（ ）特性。"
  options={[
    "A. 原子性 (Atomicity)",
    "B. 一致性 (Consistency)",
    "C. 隔离性 (Isolation)",
    "D. 持久性 (Durability)"
  ]}
  answer="A"
  explanation="【真题考点：ACID特性辨析】\n- 原子性：要么全做，要么全不做（本题场景）。\n- 一致性：事务前后数据状态逻辑一致（如总金额不变）。\n- 隔离性：并发事务互不干扰。\n- 持久性：提交后永久保存。\n题目强调的是'扣款'和'入账'两个动作必须作为一个整体，要么都成，要么都败，这是典型的原子性。"
/>

<ExerciseBox
  questionId="ch04-02-adv"
  question="企业需要构建一个系统来支持高层管理者的年度战略决策。该系统需要分析过去10年的销售数据、市场趋势和竞争对手情报。与传统的业务交易系统（OLTP）相比，该系统（数据仓库/OLAP）在设计上最显著的特点是（ ）"
  options={[
    "A. 关注数据的实时更新，响应速度在毫秒级",
    "B. 采用规范化设计（3NF）以减少数据冗余",
    "C. 面向主题组织数据，支持复杂的分析查询，允许数据冗余",
    "D. 只存储最近3个月的数据以提高查询效率"
  ]}
  answer="C"
  explanation="【真题考点：数据仓库 vs 数据库】\n- 数据库(OLTP)：面向业务（交易），实时性高，遵循范式（减少冗余），存当前数据。\n- 数据仓库(OLAP)：面向主题（分析），稳定性高，反范式（允许冗余以换取分析速度），存历史数据（海量）。\n本题场景是'战略决策'、'10年数据'，明显是数据仓库的应用。"
/>

<ExerciseBox
  questionId="ch04-03-adv"
  question="在进行数据库设计时，如果一个表中的非主属性不仅依赖于主键，还依赖于其他非主属性（即存在传递依赖），那么该表只满足（ ），可能会导致数据冗余和更新异常。"
  options={[
    "A. 第一范式 (1NF)",
    "B. 第二范式 (2NF)",
    "C. 第三范式 (3NF)",
    "D. BC范式 (BCNF)"
  ]}
  answer="B"
  explanation="【真题考点：范式判定】\n- 1NF：属性原子性。\n- 2NF：在1NF基础上，消除非主属性对主键的'部分依赖'（主要针对联合主键）。\n- 3NF：在2NF基础上，消除非主属性对主键的'传递依赖'。\n题目明确指出'存在传递依赖'，说明它未能达到3NF的要求，因此最高只满足2NF。"
/>

## 重点总结

### 本章必记考点 ⭐⭐⭐⭐

1. **数据库三级模式**：外模式(用户视图)、模式(逻辑结构)、内模式(物理存储)
2. **ACID特性**：原子性、一致性、隔离性、持久性
3. **范式**：1NF原子性、2NF完全依赖、3NF消除传递依赖
4. **数据仓库vs数据库**：OLAP决策支持 vs OLTP业务处理
5. **大数据5V**：Volume、Velocity、Variety、Value、Veracity
